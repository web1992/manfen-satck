# Outcome-Oriented Execution

优化可验证的既定终态，而非维持顺滑的中间态。

**Why:** 让每个中间步骤都完全稳定，往往会造出长期存在的临时兼容代码债务。收敛到目标架构，并在明确的验证边界上证明正确性。

**Core rule:**
- 终态完整性优先于过渡期的稳定性
- 在已计划、范围明确且可逆的前提下，可接受中间阶段的破坏

**Guardrails:**
- 用于有明确阶段边界的计划内重写与迁移
- 声明哪些地方可接受临时破坏
- 迁移期间对正在改动的区域保持高信号检查
- 计划完成时要求完整的静态与运行时验证
